## 작업 규칙(사용자 지시)
- 항목 1건을 끝낼 때마다 버그 테스트를 하고 커밋한다.
  - 테스트 추가, `cargo fmt`, `cargo clippy --release --all-targets -- -D warnings`, `cargo test --release`를 돌린다.
- 작업 과정과 질문은 한글로 쓴다.
- egui 창 전체를 불필요하게 다시 그리지 않게 하고, 메모리를 최적화한다. 그래픽 카드가 없는 사용자도 있다.
- 기능을 구현한 뒤에는 바꾼 코드와 연동된 기능을 고려해 예상 버그 목록을 만들고 검증한다. 창에서 자동으로 시험할 수 없는 항목은 목록으로 정리해 사용자에게 검증을 요청한다.
- 한도:
  - 5시간 한도가 리필되는 시각 1분 뒤로 작업 재개를 예약한다(CronCreate, 일회성). 작업이 끝날 때까지 다시 예약한다.
  - 주간 사용량이 98%가 되면 멈춘다. 진행 상황·미검증 항목·남은 작업을 이 파일에 자세히 남기고 커밋·푸시한다.
- 모두 끝나면 커밋한 뒤, 항목별 수동 검증 목록과 검증 방법을 써서 사용자에게 요청한다.
- 릴리즈·푸시는 요청이 있을 때만 한다(위의 98% 예외만 있음).
- 기존 규칙:
  - 작업일지 `docs/WORKLOG-2026-11-18-usability-v2.md`를 갱신한다.
  - 안내 문구를 바꾸면 `src/guide.rs`의 GUIDE_VERSION을 올린다(지금 16).
  - 커밋 트레일러는 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`이다.
  - 빌드 전에 ohmemojang.exe를 끈다.
  - 시험용 프로필에서 먼저 확인하고, 실제 데이터로 다시 띄운다.

## 사용자 결정(2026-11-20 질문 답)
- 자동 실행과 클립보드 수집은 기본 켜기로 한다. 기존 사용자도 업데이트 때 한 번 켠다.
- 자동 실행:
  - 24H2에서는 트레이 아이콘도 없었다(프로그램이 아예 안 켜짐). 다른 Windows 버전은 확인 안 됨.
  - 자동 실행 때는 트레이 + 시작 알림을 보인다. 메인 창은 열지 않는다.
  - 스탠딩 캘린더와 꺼내 둔 스티커는 종료 전 상태 그대로 떠야 한다.
- 스탠딩 캘린더 기능 활성화 옵션:
  - 기본은 끔이다. 켜면 네 기능의 체크박스가 나오고, 기본은 모두 체크다.
  - 네 기능: 날짜 + 버튼으로 새 메모, 날짜 끌기로 기간 일정, 스티커 끌어 놓아 일정 등록, 메모 막대 클릭·우클릭.
- 메인 창 선택 시 메모 맨 앞으로(기본 켬):
  - 메인 창 안을 클릭하면 스티커·1단·2단 접기 창이 메인 창보다도 앞에 온다.
  - 작업표시줄에서 메인 창을 고르면 메인 창이 스티커 앞에 온다.
  - 캘린더 분리창은 해당하지 않는다.
- 저장 형식:
  - 이미 SQLite(`data.db`)이고, 이미지는 파일이다.
  - DB를 다시 읽어 확인한 뒤 `data.json`과 남아 있는 `data.before-db.json`을 지운다. `backups` 폴더의 백업은 그대로 둔다.
- 흰 창(멀티 모니터 노트북의 튜토리얼 깨짐, 가끔 흰 스티커):
  - 원인을 조사한 뒤 그리기 방식을 고친다. 크고 위험한 변경도 진행한다. 바꿔서 생기는 위험은 미리 철저히 검증한다.
  - 이 PC에서 Intel로 그리면 모든 창이 하얗게 나왔다(작업일지 '전역 최적화 3').
- 시험 권한:
  - 엑셀을 열어 표를 복사해도 된다. 새 통합 문서를 쓰고, 저장하지 않고 닫는다. 클립보드는 시험 뒤 되돌린다.
  - Win+D를 보내도 된다.
  - 자동 실행 레지스트리를 바꿔도 된다. 옛 개발용 항목(`OmniMemoJang`, debug 경로)도 지운다.
  - 실제 데이터 앱을 재시작해도 된다.
