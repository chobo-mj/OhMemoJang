# 이모지 입력 (Win+.)

## 원인
😀 같은 이모지는 UTF-16에서 두 조각(서로게이트 쌍)으로 나뉜다. 이모지 창(Win+.)과 `SendInput`은 두 조각을 키 입력 두 번으로 따로 보낸다.
winit 0.30.13 Windows 키보드 처리는 첫 조각 뒤에 바로 글자 메시지가 오지 않으면 그 조각만으로 키 이벤트를 끝낸다. 그 조각은 혼자서는 올바른 글자가 아니라서 버려지고, 두 번째 조각도 혼자 와서 버려진다.
붙여넣기(Ctrl+V)는 이 길을 거치지 않아서 원래부터 됐다.

## 수정
- `vendor/winit`: winit 0.30.13을 복사하고 `Cargo.toml`의 `[patch.crates-io]`로 연결했다.
  - `src/platform_impl/windows/keyboard.rs`에 `join_surrogates`를 추가했다. 혼자 온 첫 조각은 들고 있다가 다음 키 입력의 두 번째 조각 앞에 붙이고, 다른 글자가 오면 버린다.
  - 바꾼 곳에는 "OhMemoJang patch"라고 적어 두었다.
- 이모지 뒤에 붙는 모양 바꾸기 문자는 글꼴에 모양이 없어 □로 보였다(이모지 창의 ❤ 뒤 U+FE0F, 피부색 U+1F3FB–1F3FF, 결합 문자 U+200D 등).
  - 폭이 0인 빈 글꼴(`composer::invisible_font`, 코드로 만든 cmap format 12)을 모든 글꼴 묶음의 맨 뒤 대체 글꼴로 넣어 보이지 않게 했다.
  - 글자 자체는 그대로 저장되므로, 다른 프로그램에 붙여 넣으면 원래 모양(피부색 등)으로 보인다.

## 확인
- 자동 테스트 282개(빈 글꼴 폭 테스트 추가)가 통과했다.
- 실제 프로그램에서 확인했다(따로 만든 시험 프로필):
  - 키 입력으로 넣은 "A😀B👍🏻C"가 그대로 들어간다(이전엔 "AB"와 "C"만 남음).
  - 실제 Win+. 창에서 Enter로 고른 ❤가 들어가고 뒤에 □가 없다.
  - 한글 입력기로 "가나 한글"을 쳐도 정상이다.

## 남는 한계
- 화면의 이모지는 검은색 한 가지 색이다. 화면을 그리는 도구(egui)가 컬러 글꼴을 그리지 못한다.
- 내장 이모지 글꼴에 없는 최신 이모지는 여전히 □로 보일 수 있다.
- 가족·직업처럼 여러 이모지를 이어 붙인 이모지는 조각마다 따로 보인다.
- winit을 새 버전으로 올릴 때 `vendor/winit`의 수정 부분을 다시 옮겨야 한다.
