## C12 알람 설계

- 메모 필드: `alarm_repeat: u8`(REPEATS 순번), `alarm_lead: u16`(분), `alarm_more: Vec<NaiveDateTime>`. 예전 저장 파일은 기본값(반복 없음)으로 읽힌다.
- `due_now`는 메모마다 알람 하나만 돌려준다: 본 알람 → 지난 추가 알람 → 미리 알림 순서.
- 반복 알람의 ‘확인’은 `next_repeat`로 지금 이후 첫 시각으로 넘긴다(며칠 놓쳤어도 한 번만 울림). 매월 31일은 짧은 달의 말일로 맞춘다.
- 반복 알람의 ‘5분 뒤’는 추가 알람을 하나 넣는다. 본 알람 시각(반복 기준)이 바뀌지 않게 하려는 것.
- 미리 알림을 확인하면 `(메모, 본 알람 시각)`을 기억해 다시 울리지 않는다. 이 기억은 저장하지 않아서, 미리 알림 구간에 프로그램을 다시 켜면 한 번 더 울릴 수 있다.
- Windows 알림 버튼 인자는 `done:14p`처럼 어느 알람인지 글자(m 본 알람, p 미리, x 추가)를 붙인다. 예전 형식(`done:14`)도 읽는다.

## C13 글자 색 설계

- `Format`에 `color`, `highlight`(팔레트 순번, 0은 없음)를 더했다.
- 저장은 기존 `spans` 튜플을 건드리지 않고 `TabRec.span_colors`를 나란히 둔다. 색을 하나도 안 쓴 탭은 비워 두어 저장 파일이 그대로다.
- 색을 칠할 때는 선택한 글자마다 지금 서식을 그대로 두고 색만 바꾼다(굵게 등이 풀리지 않음).
- 형광펜만 칠하고 글자 색이 기본이면, 어두운 테마에서도 읽히게 글자를 진한 색으로 그린다.
- 표 칸에는 아직 색이 저장되지 않는다(표 칸 서식은 예전 4가지 그대로).

## v2.0.1 이후: 검색 단축키, 빈 일정 메모

- 전역 단축키 Ctrl+Alt+F(검색)를 없앴다. 설정 › 단축키의 전역 단축키는 빠른 메모·캘린더 분리창·새 스티커 세 개만 남는다(`shortcuts: [String; 3]`; 예전 설정 파일의 네 번째 값은 읽지 않는다).
- 메인 창에서는 어느 화면이든 Ctrl+F를 누르면 왼쪽 검색창으로 커서가 간다(`main_shortcuts` → `search_shortcut`). 설정 화면은 닫히고, 사이드바가 접혀 있으면 열고, 아이콘만 보이는 좁은 폭이면 200으로 넓혀 검색창이 보이게 한다. 보던 화면은 그대로다.
- 전체메모의 ‘목록에서 찾기’는 더 이상 Ctrl+F를 쓰지 않는다(입력칸을 눌러 쓴다). 찾아 바꾸기는 Ctrl+H 그대로. 스티커 안의 Ctrl+F는 예전대로 전체메모 찾기로 간다.
- 캘린더에서 날짜를 끌어 만든 메모를 제목·본문·그림·표 없이 닫으면 영구 삭제한다(`drafts`, `drop_blank_drafts`, 휴지통을 거치지 않음). 무엇이든 쓴 메모, 다른 방법으로 만든 빈 메모는 그대로다.
- 테스트: `ctrl_f_in_the_main_window_puts_the_cursor_in_the_search_box`, `a_calendar_drag_memo_closed_blank_is_erased_and_a_written_one_stays`. GUIDE_VERSION 7.

## 설정에서 같은 메뉴로 돌아가기

- 증상: 내 작업실을 보다가 설정을 연 뒤 다시 ‘내 작업실’을 누르면 설정 화면이 그대로였다. 설정은 ‘보던 페이지가 바뀌면 닫는다’로만 닫혀서, 같은 페이지를 누르면 아무 일도 없었다.
- 수정: 메뉴(넓은 사이드바·아이콘 사이드바)의 페이지 버튼은 `open_page`로 페이지를 정하고 설정을 닫는다. 설정이 열려 있는 동안에는 뒤의 페이지 버튼을 선택 표시하지 않는다.
- 테스트 `choosing_the_page_behind_the_settings_leaves_the_settings`.
- 고침: 빈 일정 메모를 지운 뒤에도 캘린더·목록에 ‘삭제된 메모’ 줄이 남던 것. 목록은 입력이 있어야 다시 계산하는데, 지우기는 닫은 다음 프레임에 입력 없이 일어나서 예전 목록(제목만 ‘삭제된 메모’로 바뀐)이 그대로 보였다. 지울 때 `lists::CHANGES`를 올려 바로 다시 계산하게 했다.

## 일정 막대 양끝 끌어 기간 바꾸기, 본문 우클릭 삭제

- 캘린더 일정 막대의 실제 시작·끝 칸(주가 넘어가며 잘린 끝은 제외)에 7px 손잡이를 두었다(`band_edges`). 마우스를 올리면 ↔ 커서와 얇은 선이 보인다. 메인 캘린더와 캘린더 분리창이 같은 `calendar_bands`를 쓰므로 두 곳 모두 동작한다.
- 끄는 동안(`band_resize`, 창별)에는 반대쪽 끝을 고정하고 포인터 아래 날짜(`grid_day`)까지를 바로 메모 기간으로 바꾼다(`Note::set_days`). 포인터 이동은 입력으로 세지 않으므로 바꿀 때 `lists::CHANGES`를 올려 막대를 다시 그린다. 놓으면 "A ~ B 기간 일정으로 바꿨어요" / "A 당일 일정으로 바꿨어요" 안내.
- `set_days`: 이날까지 업무를 풀고(마감일과 막대가 어긋나지 않게), 시작일·일수를 정한다. 하루가 되면 당일 일정. 완료된 메모는 늘려도 모든 날이 완료로 남고, 하루로 줄이면 그날의 완료 여부를 따른다.
- 반복 일정과 ‘일정’ 기준이 아닌 캘린더(작성일·알람 기준)에서는 손잡이를 두지 않는다.
- 스티커 본문 우클릭 메뉴에 ‘스티커 휴지통으로’, ‘스티커 영구삭제…’를 더했다. … 더보기의 같은 동작(`trash_note`, 확인 창이 있는 `request_purge`)을 부른다.
- 테스트: `dragging_a_band_end_makes_a_stretch_and_back_a_single_day`, `stretching_a_deadline_memo_makes_it_a_plain_schedule`, `a_done_memo_stays_done_when_its_days_change`, `the_pointer_picks_the_grid_day_and_stays_inside_the_grid`. GUIDE_VERSION 8.

- 메뉴·팝업이 자기 창에 갇히던 문제: egui의 `context_menu`·`popup_below_widget`은 같은 창 안에만 그려져서, 작은 스티커나 캘린더 분리창·대화 상자에서는 잘렸다. 새 모듈 `src/float.rs`가 메뉴를 테두리 없는 항상 위 작은 창으로 띄운다(기존 스티커 ⋯ 메뉴의 `studio::menu_window` 재사용). 메뉴는 항목을 누르면 닫히고(글 입력칸·`keep_open` 행 제외), 팝업은 내용이 `close_popup()`을 부를 때 닫힌다. 둘 다 Esc, 원래 창을 누를 때, 포커스가 다른 곳으로 간 지 0.3초 뒤 닫힌다.
- 바꾼 곳: 스티커 본문 우클릭(편집·읽기 전용), 본문 탭 우클릭(‘숨긴 탭 보이기’ 하위 메뉴는 같은 메뉴 안에 펼침), 링크 이름 메뉴, 표 우클릭(‘표 삭제…’는 같은 메뉴에서 한 번 더 확인), 스티커 아래 툴바 팝업(글꼴·크기·색·투명도), 시간 고르기 팝업(알람·일정 창), 목록 행 우클릭(분리 캘린더의 날짜 목록 포함), 인라인 편집의 프로젝트·연결 메모 팝업, 캘린더 분리창 우클릭 보기 메뉴.
- 메인 창 안의 위키·전체메모·보드 메뉴는 창이 커서 그대로 두었다(하위 메뉴가 많아 같은 방식으로 옮기려면 따로 손봐야 함).
- 클립보드 히스토리: DB 스키마 2(`comment`, `pinned` 열, 1에서 자동 추가). 정렬은 압정 → 코멘트 있음 → 복사한 순(최신 먼저). 페이지 커서를 (순위, 시각, id)로 바꿔 순서가 페이지를 넘어도 같다. 검색이 코멘트도 찾는다. 압정 항목은 개수·기간·용량 자동 정리에서 빠진다(직접 하는 ‘이전 삭제’, ‘전체 삭제’는 그대로 지움). 행: 내용 · 코멘트(입력칸, 포커스를 잃을 때 저장) · 압정 · 복사 · 삭제. 다섯 필터 탭 모두 같은 목록을 쓴다.
- 편의기능: 표·이미지 모아보기에 압정(메모·탭·블록 id로 기억), 링크·즐겨찾기에 코멘트와 압정(주소로 기억). 링크는 압정 → 코멘트 → 가져온 순. 즐겨찾기 목록 자체도 이제 저장된다(전에는 실행 중에만 유지).
- 스탠딩 캘린더 ‘지원 안 됨’은 Windows 11 24H2(빌드 26100)에서만 보인다(`system::standing_unsupported_on`). 25H2(26200) 이후는 지원으로 본다.
- 테스트: float 열기·닫기, 24H2 판정, 클립보드 정렬·페이지·자동 정리·스키마 이전, 즐겨찾기 정렬, 압정·코멘트 저장 왕복. GUIDE_VERSION 10.

## 스탠딩 캘린더: 아이콘 아래로 되돌림, 해제 버튼, 끌어 놓기

- 증상(이 PC, Windows 11 25H2): 스탠딩 캘린더 위에 바탕화면 아이콘을 둘 수 없고, 해제 버튼이 듣지 않았다.
- 원인: 11-17 수정(fa3d943)이 새 바탕화면 구조(Progman 아래 `SHELLDLL_DefView`·`WorkerW`가 자식)에서 캘린더를 자식 창으로 붙이지 않고 바탕화면 바로 위의 최상위 창으로 두게 했다. 그러면 캘린더가 아이콘을 덮는다. 또 그 창은 클릭을 직접 받아서, 같은 클릭을 바탕화면 클릭 감시(마우스 훅)도 잡았다. 훅이 먼저 풀고 다음 프레임에 창의 클릭이 다시 고정해, 해제가 안 되는 것처럼 보였다.
- 수정(`win_style::desk::pin_under_icons`): 새 구조에서는 배경화면 앱들이 하는 방식으로 캘린더를 Progman의 자식으로 만들어 아이콘 층 바로 뒤, 배경(WorkerW) 앞에 둔다. Progman은 자기 그리기 표면이 없어 일반 자식 창은 안 보이므로, 불투명(255) 레이어드 창으로 만든다. 해제하면 레이어드를 뺀다. Explorer가 순서를 바꾸면 `keep_on_desktop`이 250ms마다 아이콘 층 바로 뒤로 되돌린다. Windows 11 24H2(26100)에서는 예전처럼 최상위 창 방식으로 둔다.
- 해제 직후 0.6초 동안은 스탠딩 버튼 클릭을 무시한다(`Dock::unpinned_at`). 그래서 같은 클릭이 두 경로로 들어와도 다시 고정하지 않는다.
- 스탠딩 중인 캘린더 위에 스티커를 끌어 놓아도 일정이 되지 않는다(`schedule_target_at`이 그 창의 날짜 칸을 건너뜀). 24H2 이외 버전도 마찬가지다.
- 확인(시험용 프로필, 이 PC 25H2): 고정하면 캘린더가 Progman 안에서 `SHELLDLL_DefView`와 `WorkerW` 사이에 놓였다. 화면에 보이고, 바탕화면 아이콘이 그 위에 그려졌다. Ctrl+Alt+C로 풀면 제목 표시줄이 있는 일반 창으로 돌아오고 레이어드 표시도 빠졌다.
- 확인 못 함: 바탕화면에서 스탠딩 버튼을 직접 눌러 푸는 것(바탕화면 클릭 권한을 받지 못함), 스티커를 실제로 끌어 놓는 것(단위 테스트만), 24H2 PC.
- 테스트 `nothing_dropped_on_a_standing_calendar_becomes_a_schedule`. GUIDE_VERSION 11.

## 바탕화면에서 스티커를 옮기면 일정 날짜가 바뀌던 문제

- 증상(사용자 확인, 25H2): 스탠딩 캘린더 위로는 일정이 들어가지 않지만, 이미 일정이 있는 메모의 스티커를 바탕화면에서 옮기면 캘린더 안에서 날짜가 바뀌었다.
- 원인: 스티커를 놓을 날짜는 최근 1초 안에 그려진 캘린더 칸 중에서 고른다. 최소화되었거나 다른 창·바탕화면 뒤에 가려진 메인 창 캘린더도 칸을 계속 그리고 있어 후보가 됐다. 창 순서 판정(`window_rank_at_origin`)은 최소화된 창을 찾지 못해도 후보에서 빼지 않았다.
- 수정(`system::window_seen_under_pointer`, `schedule_target_at`): 포인터 아래의 창을 위에서부터 훑어, 실제로 그 자리에 보이는 우리 캘린더 창만 날짜를 받는다. 끌고 있는 스티커·메뉴 같은 우리 창은 투과해서 보고, 다른 프로그램 창이나 바탕화면이 먼저 나오면 아무 날짜도 받지 않는다. 숨은 창, 최소화된 창, 가려진(cloaked) 창, 클릭 투과(WS_EX_TRANSPARENT) 창은 건너뛴다.
- 확인(시험용 프로필): 보이는 메인 캘린더 11/24 칸에 스티커를 놓으면 11/24로 바뀐다(그대로 동작). 메인 창을 최소화한 뒤 같은 자리(바탕화면)에 놓으면 스티커만 옮겨지고 날짜는 11/24 그대로였다.
- 단위 테스트에서는 실제 창이 없어 이 확인을 건너뛴다(`cfg(test)`).

## 스탠딩 중 바탕화면에서 마우스가 가끔 끊기던 문제

- 증상(사용자): 프로그램이 켜져 있을 때 바탕화면에서 마우스를 움직이면 가끔 프레임이 끊기고, 프로그램을 끄면 사라졌다.
- 원인으로 본 것: 스탠딩 중에는 캘린더 자리를 지키려고 0.25초마다 프로그램 전체를 다시 그렸다(`request_repaint_after(250ms)`). 아이콘 아래로 옮긴 뒤로는 그 캘린더가 바탕화면(Progman) 안의 레이어드 창이라, 다시 그릴 때마다 바탕화면 전체가 다시 합성된다. 스탠딩이 아닐 때는 주기적으로 깨는 곳이 없다(대기 최대 30초).
- 수정: 자리 지키기를 바탕화면 클릭 감시 스레드로 옮겼다. 이 스레드가 0.25초 타이머로 순서만 확인하고, 틀어졌을 때만 `SWP_ASYNCWINDOWPOS`로 바로잡는다. 그래서 감시 스레드가 UI 스레드를 기다리지 않고, 마우스 훅도 막히지 않는다. 프로그램은 스탠딩 때문에 다시 그리지 않는다. 풀린 창(도구 창 표시가 빠진 최상위 창)은 건드리지 않아서, 해제 직후의 타이머 한 번이 창을 내리지 않는다.
- 측정(시험용 프로필, 스탠딩 중 10초): 프로그램 CPU 172ms → 16ms.
- 확인: 고정하면 아이콘 아래에 보이고 메모 막대도 보인다. 창 순서를 일부러 배경 아래로 내리면 0.6초 안에 아이콘 바로 뒤로 돌아온다. Ctrl+Alt+C로 풀린다.
- 확인 못 함: 마우스 끊김이 사라졌는지는 사용자 화면에서 확인해야 한다.
